# 档案详情页：在浏览器里浏览原始扫描件

## Context（为什么做）

现在搜索页只能看到 OCR 文本（标题、相对路径、页数、正文高亮片段）——检索命中的是识别结果，**看不到原始扫描件**，使用者无法核对原件。

目标：搜索结果里点标题 → 进入详情页，在浏览器里**逐页查看该档案的原始图片**，不经过 OCR、不依赖 ES 里的文本；呈现方式为「一页一图 + 上一页/下一页」。

探索阶段确认的事实（都已核对源码与你的实际数据）：

- 一份档案 = 扫描根目录下的一个**叶子目录**；一页 = 目录内的一个图片文件。页序按文件名 `sort.Strings` 字典序（[scanner.go](file:///Users/zen/github/eDocuments/internal/scanner/scanner.go#L114)），支持 `.jpg/.jpeg/.png/.tif/.tiff`（[scanner.go](file:///Users/zen/github/eDocuments/internal/scanner/scanner.go#L19-L25)）。
- 实测 `deploy/data/scan` 下**全部是 `.jpg`**（360 张，5 份档案，层级为 `1998盒子/<子目录>`）→ 浏览器可直接显示，**不需要服务端转码，也不涉及 TIFF**。
- 搜索结果 [store.Hit](file:///Users/zen/github/eDocuments/internal/store/store.go#L14-L21) 已带 `ID` / `Title` / `RelativePath` / `PageCount`，足以定位档案。
- 扫描根目录在容器里**已是只读挂载**，且 compose 已设置 `EDOCS_SCAN_ROOT=/data/scan`（[deploy/docker-compose.yml](file:///Users/zen/github/eDocuments/deploy/docker-compose.yml#L40-L43)）——但 `serve` 目前没读这个变量。本次直接把它接上，**compose 一行都不用改**。
- Web 层是「单模板 + 内嵌 CSS」结构（[template.go](file:///Users/zen/github/eDocuments/internal/web/template.go)），`NewHandler(store)` 只收 store，路由只有 `/` 与 `/search`（[web.go](file:///Users/zen/github/eDocuments/internal/web/web.go#L32-L37)）。
- `go.mod` 为 `go 1.27.1` → 可用 `os.OpenRoot`（Go 1.24+）做防穿越的文件访问。

## 方案

全部在 `internal/web` 内完成，**不引入任何新依赖**。新增两个路由 + 一个链接：

| 路由 | 作用 |
|---|---|
| `/doc?p=<相对路径>&n=<页号>` | 详情页，显示该档案第 n 页原图 |
| `/doc/image?p=<相对路径>&f=<文件名>` | 原图字节流 |
| 搜索卡片标题改链接 | 从结果点进详情 |

## 改动清单

### 1. `internal/scanner/scanner.go` — 抽出图片列举规则并导出

把 `buildDocument` 里「读目录 + 按扩展名分类」那段（[scanner.go](file:///Users/zen/github/eDocuments/internal/scanner/scanner.go#L93-L106)）抽成包内函数：

```go
// readImages 读 dir，按受支持扩展名分成图片与非图片两组。
func readImages(dir string) (images, nonImages []string, err error)
```

再导出一个给 web 层复用的小函数，让**页序与扩展名清单只有一份**：

```go
// PageFiles 返回 dir 下受支持的扫描图片文件名，按页序（文件名字典序）排序。
func PageFiles(dir string) ([]string, error)
```

`buildDocument` 改为调用 `readImages`，其余逻辑（含「发现子目录则跳过」[scanner.go](file:///Users/zen/github/eDocuments/internal/scanner/scanner.go#L96-L99)、空目录告警、非图片告警）保持原样，**行为不变**。

### 2. `internal/web/web.go` — 路由、handler、详情数据

- `NewHandler(s store.Store, scanRoot string)` 增加扫描根目录参数（[web.go](file:///Users/zen/github/eDocuments/internal/web/web.go#L23)）
- `Routes()` 追加两条路由（[web.go](file:///Users/zen/github/eDocuments/internal/web/web.go#L32-L37)）：`/doc` → `h.doc`，`/doc/image` → `h.docImage`
- `pageData` 增加 `Doc *docView` 字段，新结构体字段：`Title, RelPath, Page, Total, File, PrevPage, NextPage, HasPrev, HasNext`（[web.go](file:///Users/zen/github/eDocuments/internal/web/web.go#L79-L89)）
- `h.doc` 流程：取 `p` → 用 `os.OpenRoot(scanRoot)` 打开该目录 → `scanner.PageFiles` 取页列表 → 解析 `n`（缺省 1，越界夹取到 `1..len`）→ 渲染详情

## 安全考虑

- **路径穿越**：`p` / `f` 都来自 URL。用 `os.OpenRoot(scanRoot)` 打开，`os.Root` 保证解析结果不逃出根目录；手改 URL（如 `p=../../etc`）只会得到 404。
- **文件类型**：只服务 `scanner.PageFiles` 列举出的文件名（等价于限定那 5 种图片扩展名），目录内的其他文件不会被吐出去。
- **只读**：容器里扫描根目录本就是 `:ro` 挂载，服务端无任何写操作。
- **端口**：仍只暴露 8080，不新增端口。

## 明确不做

- 不做缩略图 / 服务端缩放（实测全是 jpg，内网直出原图即可；服务端缩放会引入 CPU 与复杂度）
- 不做详情页的 OCR 文本对照（你选择只看原图）
- 不做批量导出、下载打包、权限认证（维持现有内网信任边界）
- 不改 compose、不改 ES mapping、不改 `Store` 接口
