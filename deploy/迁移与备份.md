# 迁移与备份说明（换机器 / 换内网）

本说明面向已在一台机器上完成扫描与入库，需要把整套系统搬到另一台机器继续使用的场景。
交付包就是本目录（`docker-compose.yml` + 本说明），数据目录在首次部署时创建。

## 一、先看清三份数据，谁必须搬

| 数据 | 位置 | 性质 | 迁移时 |
|---|---|---|---|
| 扫描件原件 | `data/scan/`（默认位置，可用 `SCAN_ROOT` 覆盖） | 绑定挂载的普通文件 | **必须带走**，详情页查看原图靠它 |
| OCR 文字结果 | `data/cache/` 下的 `*.json` | 绑定挂载的普通文件 | **必须带走**，否则要重新 OCR |
| 检索索引 | Docker 命名卷 `deploy_es-data` | 容器私有数据 | **不必带走**，可由上表第二项重建 |

结论：**不需要拷 Docker 卷**。索引是派生数据，把扫描件和 JSON 缓存带过去，重新生成一遍即可。

## 二、在 A 机器上：打包数据

```bash
cd deploy
docker compose stop            # 先停服务，保证文件状态一致（切勿加 -v 参数）

# 把两个数据目录连同内部层级一起打包
tar -czf edocs-data.tgz data/scan data/cache
```

把 `edocs-data.tgz` 拷到 B 机器，放到交付包目录下。

## 三、在 B 机器上：恢复

```bash
# 1. 装好 Docker 与 Docker Compose，把交付包放到一个名为 deploy 的目录里
#    （目录名有讲究，见「四、注意事项」第 3 条）

# 2. 解开数据包，得到 data/scan 与 data/cache
tar -xzf edocs-data.tgz

# 3. 起数据库（首次启动要等健康检查通过）
docker compose up -d elasticsearch

# 4. 用 JSON 缓存重建索引：只写索引，不重新 OCR
docker compose run --rm edocs index --recreate --reindex

# 5. 起搜索服务
docker compose up -d
```

浏览器访问 `http://<B 机器的内网IP>:8080` 即可检索。第 4 步的 `--recreate` 表示先删掉
可能存在的旧索引再重建；B 机器是全新环境时加不加都一样，为省事可以固定写这一条。

## 四、注意事项

1. **`data/scan` 的目录结构不能改。** 每份档案的 ID 是它相对扫描根目录路径的哈希，层级一变
   ID 就变；详情页也是按相对路径去扫描件目录取原图。B 机器上扫描件放在别处时，用
   `SCAN_ROOT=/path/to/scan` 指定新根目录，但根目录以下的层级要和 A 机器一致。

2. **`data/cache` 要整个目录一起搬。** 缓存文件名就是档案 ID（sha256），是增量入库与重建索引
   的依据。丢了它，B 机器上就只能重新 OCR 全部扫描件。

3. **B 机器上交付目录要叫 `deploy`。** compose 的项目名取自目录名，命名卷随之命名为
   `deploy_es-data`。目录改名会导致卷名变化、数据对不上（本方案不搬卷时影响不大，但保持一致更省心）。

4. **不要执行 `docker compose down -v`。** `down` 只停容器、不动数据；加 `-v` 会连索引数据卷一起删除。

5. **迁移后自查。** 随便搜几个词，对照 A 机器的结果：命中条数、标题、高亮片段应完全一致。

## 五、可选：连 ES 数据卷一起搬

只有当 JSON 缓存也丢失、又不想重新 OCR 时才有必要走这条路。索引数据是容器私有格式，
并且与镜像内的 ES 版本绑定，跨版本直接拷贝可能读不出来，因此不建议常规使用。

```bash
# A 机器：停掉 ES 后整卷导出
docker compose stop elasticsearch
docker run --rm -v deploy_es-data:/from -v "$PWD":/backup alpine \
    tar -czf /backup/es-data.tgz -C /from .

# B 机器：确保交付目录名为 deploy，先让 compose 建出同名卷，再停掉容器把内容解进去
docker compose up -d elasticsearch && docker compose stop elasticsearch
docker run --rm -v deploy_es-data:/to -v "$PWD":/backup alpine \
    tar -xzf /backup/es-data.tgz -C /to
docker compose up -d
```

## 六、常见问题

| 现象 | 原因与处理 |
|---|---|
| 迁移后搜索无结果或结果为空 | 漏了第 4 步 `index --recreate --reindex`，或 `data/cache` 没带过来；补跑该命令 |
| 列表能搜到，但点进去看不到原图 | `data/scan` 没带过来，或相对层级和 A 机器不一致 |
| 提示连不上数据库 | ES 还没就绪，等健康检查通过后再执行索引与服务命令 |
| 想确认数据都还在 | `ls data/cache \| wc -l` 看缓存文件数，`ls data/scan` 看扫描件目录是否完整 |
